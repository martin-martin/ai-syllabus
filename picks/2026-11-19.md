# The Unreasonable Effectiveness of Recurrent Neural Networks

**Who:** Andrej Karpathy, then a PhD student at Stanford (later OpenAI founding member and Tesla's director of AI)
**What / when:** blog post, May 21, 2015, karpathy.github.io
**Full piece:** https://karpathy.github.io/2015/05/21/rnn-effectiveness/
**Jump in here:** https://karpathy.github.io/2015/05/21/rnn-effectiveness/#source-code (section "Source Code", the "Brief digression" about frameworks, two paragraphs plus a four-item list, ~2 min)

## Why this one

The post that made character-level language models famous: an LSTM trained on Shakespeare, Wikipedia, LaTeX and Linux source code, generating text one character at a time. Foundational era after yesterday's current AI 2027 pick, and a different person and format (blog) than the last few days. The "Source Code" section has a small time capsule for a Python audience: in 2015 Karpathy's favorite framework was Torch 7 (Lua), and he lists what he wishes an effective framework had, including a separate code base in "ideally Python" and no compilation step. That reads a lot like a description of what PyTorch later became.

## What's said there

> "An entirely separate code base in a scripting language (ideally Python) that operates over Tensors and implements all Deep Learning stuff (forward/backward, computation graphs, etc)" (section "Source Code", list item 2, text verified: yes)

> "The code is written in Torch 7, which has recently become my favorite deep learning framework. I’ve only started working with Torch/LUA over the last few months and it hasn’t been easy" (same section, text verified: yes)

> "NO compilation step (or at least not as currently done in Theano)." (same section, list item 4, text verified: yes)

- Karpathy releases char-rnn, written in Torch 7 (Lua). He mentions digging through raw Torch code on GitHub and asking on their gitter to get things done.
- He's also used Caffe and Theano and thinks Torch "gets its levels of abstraction and philosophy right better than others".
- His wishlist: a CPU/GPU transparent tensor library, a separate code base in a scripting language (ideally Python) for forward/backward and computation graphs, easy sharing of pretrained models, and no long compilation step, because compiling hurts development time and makes debugging and logging harder.
- Context, not from the post: PyTorch (Python on top of Torch's tensor backend, eager execution) was released in early 2017. Worth double-checking the date before posting.

Alternative section in the same post, if Martin prefers the ML angle: "Visualizing the predictions and the neuron firings" (#visualizing-the-predictions-and-the-neuron-firings-in-the-rnn), where single LSTM cells turn out to track URLs, quotes or line position without being told to. Verified quote: "We just trained the LSTM on raw data and it decided that this is a useful quantitity to keep track of." (typo "quantitity" is in the original)

**C, educator's angle (longer):**

Andrej Karpathy (later OpenAI and Tesla AI) wrote "The Unreasonable Effectiveness of Recurrent Neural Networks" in 2015. It's still a fun read: an LSTM learns to write fake Shakespeare, fake LaTeX and fake Linux code, one character at a time.

Near the end there's a short aside on tools. He'd only been using Torch (written in Lua) for a few months, and describes digging through its raw source on GitHub and asking questions on their chat to get things done.

His wishlist for a better framework includes "An entirely separate code base in a scripting language (ideally Python) that operates over Tensors and implements all Deep Learning stuff (forward/backward, computation graphs, etc)", and no compilation step, because compiling makes it harder to debug and log: https://karpathy.github.io/2015/05/21/rnn-effectiveness/#source-code

Today most people learning deep learning start in Python, in PyTorch, and probably never think about this. Interesting to see how much friction there was ~10 years ago, even for someone like Karpathy.
