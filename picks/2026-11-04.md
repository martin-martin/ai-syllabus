# LLM Powered Autonomous Agents

**Who:** Lilian Weng, OpenAI at the time (personal blog, Lil'Log)

## Why this one

Written in the AutoGPT/BabyAGI summer of 2023, this post became a standard reference for how LLM agents are put together (planning, memory, tool use). Its closing "Challenges" section is a neat snapshot of what people thought was holding agents back, which is easy to hold up against today's coding and computer-use agents. It's also a nicely structured explainer, good for anyone teaching what an "agent" actually is.

## What's said there

> "However, the reliability of model outputs is questionable, as LLMs may make formatting errors and occasionally exhibit rebellious behavior (e.g. refuse to follow an instruction). Consequently, much of the agent demo code focuses on parsing model output." (section "Challenges", text verified: yes)

> "A lot of code in AutoGPT is about format parsing." (section "Proof-of-Concept Examples", text verified: yes)

- Weng lists three limitations she noticed after going through agent demos: finite context length, long-term planning and task decomposition, and the reliability of natural language as the interface between the LLM and memory/tools.
- On context: retrieval from vector stores helps, but "their representation power is not as powerful as full attention."
- On planning: LLMs "struggle to adjust plans when faced with unexpected errors, making them less robust compared to humans who learn from trial and error."
- Earlier in the post (#types-of-memory) she maps human memory types onto agent parts: sensory memory as embeddings, short-term memory as in-context learning, long-term memory as an external vector store.

**B, then vs. now:**

In June 2023, the summer of AutoGPT, Lilian Weng (then at OpenAI) wrote a long post on how LLM agents are built: planning, memory and tool use.

At the end she lists what she saw holding them back: limited context windows, models that struggle to adjust a plan after an unexpected error, and an unreliable natural language interface, where models "may make formatting errors and occasionally exhibit rebellious behavior (e.g. refuse to follow an instruction)": https://lilianweng.github.io/posts/2023-06-23-agent/#challenges

Three years later, context windows got a lot bigger and tool calls come back as structured output. I'm less sure the planning point has gone away. Which of the three would you say is still the real bottleneck?

**C, educator's angle:**

One part I like to point people to when they ask what an "agent" actually is: Lilian Weng's 2023 post "LLM Powered Autonomous Agents".

She starts from human memory (sensory, short-term, long-term) and maps each onto a piece of an agent. Sensory memory becomes embeddings of the raw input, short-term memory is whatever fits in the context window, and long-term memory is an external store the agent retrieves from: https://lilianweng.github.io/posts/2023-06-23-agent/#types-of-memory

It's a rough analogy (she says so herself, "We can roughly consider the following mappings"), but a useful first mental model, before getting into the details of retrieval or tool calling.

The "Challenges" section at the end is also fun to read today, e.g. that "much of the agent demo code focuses on parsing model output."
